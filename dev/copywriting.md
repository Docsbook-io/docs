# Copywriting Guidelines

## Objections and Answers

Canonical list — used in copy, FAQ, email sequences, ad creative.

| Objection | Our Answer |
|---|---|
| "I'm afraid to authorize GitHub" | Authorization isn't needed to look around. Set up → log in → publish. |
| "I don't want to deal with GitHub" | Funnel with a guide "how to create docs in GitHub" or through an MCP agent. |
| "I don't want to spend time on branding" | Looks great out of the box. The MCP agent reads your site's brand guidelines and configures the design itself. |
| "I need to write proper docs first" | "Upload what you have — Docsbook turns it into a site." Remove the barrier. |
| "Documentation isn't a priority" | "Every support ticket costs $5–15. Good docs cut their volume by 40%." |
| "Why not just use GitHub" | Not indexed in Google. No analytics. No AI chat. No translations. You're losing organic traffic every day. |
| "Another SaaS that'll shut down" | Data lives in GitHub. Markdown export in one click. Lifetime PRO purchase. |
| "AI translations are bad / AI will rewrite my content" | "AI is an assistant, not an author. Your texts stay yours." |
| "I want a branded site, not a generic one" | Full control over widgets, colors, fonts, custom domain, white-label. |
| "I'm not ready to pay ongoing fees" | One-time $150 purchase for small projects. Subscription only on PRO+ for high usage limits. |
| "My project is for community, not monetization" | Free plan with basic analytics. Your project will be found in search. Looks professional. |
| "Cheaper to set up Docusaurus myself" | Hours of configuration. No analytics. No SEO out of the box. Your time is worth more. |
| "A doc site will take weeks" | 5 minutes from GitHub to publishing. No code, no DevOps. |
| "Not sure it will pay off" | "Companies with quality documentation convert to trial 30% better." |

| "Translation is complicated" | "Your docs in 15 languages without translators. Every version indexed in Google separately." |
| "Will translations actually be indexed?" | Yes, each language at its own URL with hreflang. |

## Tone of Voice

### Do:
- Short sentences. Direct 2nd person ("your docs", "you publish").
- Specifics: "5 sec", "$150 lifetime", "15 languages", "40% fewer tickets".
- Comparisons to familiar benchmarks ("$200/mo cheaper than GitBook").
- Keep technical terms as-is (MCP, llms.txt, SEO, OAuth) — our audience knows them.

### Don't:
- "Enterprise-grade synergy", "revolutionize your workflow", "harness the power of AI".
- Emojis in production copy.
- Long paragraphs. If it can be a list — make it a list.
- Don't write "AI-powered" without specifics — be concrete: "AI chat trained on your docs", "AI translation into 15 languages".

### Page / Email / Post Structure:
1. Why this matters (1 line)
2. What happens without it (1–2 lines of pain)
3. How to avoid it (our solution)
4. Alternatives and why they're worse
5. Example / case study
6. Getting started (1 command / 1 click)
